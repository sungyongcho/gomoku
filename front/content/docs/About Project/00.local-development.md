# Local Development

When developing Gomoku locally, `Docker` is essential.
Requires `Docker` and `Docker Compose v2+`.

## 1. Clone GitHub repo

```bash
$ git clone git@github.com:sungyongcho/gomoku.git
$ cd gomoku
```

`alphazero/models/champion.pt` is versioned in this repository, so cloning includes the V4 champion checkpoint (iteration 222) that `configs/deploy.yaml` serves locally. The v5 checkpoint served in production is not versioned.

## 2. Apply alias.sh

```bash
$ source alias.sh
```

This provides convenience aliases: `dev-up` (full stack), `dev-up-front` (the `front` service; Compose still starts its `minimax` and `alphazero` dependencies), `dev-down` (stop all), `dev-up-debug` / `dev-up-valgrind` (debugging), and cluster/deployment helpers.

## 3. Create `.env` in project root

```.env
LOCAL_FRONT=3000
LOCAL_FRONT_NUXT_CONTENT_WS=4000
LOCAL_MINIMAX=8005
LOCAL_MINIMAX_GDB=8006
LOCAL_ALPHAZERO=8080

FRONT_WHERE=local
# Read by the local AlphaZero Docker container (the Oracle deploy uses DEPLOY_ALPHAZERO_A1_*).
DEPLOY_ALPHAZERO_CONFIG=configs/deploy.yaml # serving config; the search stops at mcts.time_limit_s
DEPLOY_ALPHAZERO_DEVICE=cpu
```

For the complete variable list and sectioned defaults, check `.env.example`.

## 4. Launch Application

Full stack (frontend + minimax + AlphaZero):

```bash
$ dev-up
```

Frontend only (no backend containers):

```bash
$ docker compose -f docker-compose.yml up --no-deps front
```

Frontend + minimax only (no PyTorch/model dependencies):

```bash
$ docker compose -f docker-compose.yml up --no-deps front minimax
```

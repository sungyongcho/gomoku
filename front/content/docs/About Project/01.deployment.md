# Live Demo Deployment

This page describes the deployment setup behind the live demo at **[sungyongcho.com/gomoku](https://sungyongcho.com/gomoku)** (including this docs site).

## Infrastructure

| Service | Host | vCPU | RAM |
|---------|------|------|-----|
| Minimax | Oracle Cloud `VM.Standard.A1.Flex` (Arm, Always Free; since Sep 2026) | 2 OCPU | 12 GB (shared) |
| AlphaZero | Oracle Cloud `VM.Standard.A1.Flex` (Arm, Always Free; since Nov 2026) | 2 OCPU | 12 GB |
| Frontend + docs | Netlify | – | – |

Both backends run as Docker containers on their own Oracle Cloud Arm VMs: Minimax since September 2026 (moved from a GCP `e2-small` VM, see `deploy/minimax/`) and AlphaZero since November 2026 (moved from a GCP `c2d-standard-4` Container-Optimized OS VM, see `deploy/alphazero-oracle/` and [Serving on a 2-Core Arm Instance](/docs/optimization/free-arm-hosting)). A Cloudflare Worker handles path-based routing (`/minimax/*`, `/alphazero/*`) to the respective backends and proxies `/gomoku/*` to the Netlify frontend.

Training used a Ray cluster with one GPU head node. In the original runs, CPU-only self-play workers generated games in parallel and sent inference requests to GPU actors through the async inference pipeline; the November 2026 v5 run moved inference into each worker (bf16) and added 12 self-play workers on the GPU head.
See [Training Pipeline](/docs/alphazero/training-pipeline) for the cluster architecture, and [Running the Training Cluster](/docs/optimization/training-infrastructure) for the November 2026 runs.

For the earlier GCP deployment (COS startup scripts, Artifact Registry image flow) and the Cloudflare Worker path routing, see [AlphaZero Deployment](/docs/alphazero/deployment).

Response times on the live demo will vary from benchmark numbers cited in the documentation: both engines run on free 2-core Arm instances to keep hosting costs at zero.
